# 终端行为监控系统 —— 安装与测试说明

本文档对应《终端行为监控系统产品说明书new.md》第一期。详细功能定义请看那份说明书，本文只讲"怎么装、怎么跑、怎么测"。

## 当前进度

- ✅ 服务端 + 数据库 + 管理网页
- ✅ 代理数据上报接口（`/api/agent/*`）
- ✅ 终端代理（Windows 服务 + 后台小程序）—— 代码已完成，编译/安装/测试步骤见 `agent/README.md`

现在可以在真实电脑上装代理、带去公司完整测试了。本文档只讲服务端部分；**终端代理的编译、安装、测试清单请看 `agent/README.md`**。

管理网页首次启动会自带 15 台模拟电脑的演示数据（近 7 天），用来验证网页本身没问题；装了真代理之后，真实电脑会按主机名自动多出现一行，与演示数据互不影响，去"设置"页把它改成好记的编号和使用人即可。

## 一、环境要求

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10/11 或 Windows Server |
| .NET SDK | .NET 8 SDK（`dotnet --list-sdks` 确认有 8.0.x；本机实测用 9.0.203 的 SDK 搭配 8.0 运行时也可以编译运行） |
| 数据库 | 无需单独安装，SQLite 文件随程序自动生成 |

检查命令：

```powershell
dotnet --version
```

没装的话去 https://dotnet.microsoft.com/download 装 .NET 8 SDK。

## 二、安装步骤（本机 / 测试机）

1. 把整个项目目录拷到测试机（或直接在当前电脑测试）。
2. 进入服务端项目目录：

   ```powershell
   cd "D:\work\01_进行中项目\Z终端行为监控系统\server\MonitorServer"
   ```

3. 还原依赖包（首次运行会自动做，也可手动执行）：

   ```powershell
   dotnet restore
   ```

4. 启动：

   ```powershell
   dotnet run
   ```

5. 看到日志里的 `Now listening on: http://localhost:5208`（端口可能不同，以实际日志为准），说明启动成功。首次启动会自动创建 `monitor.db` 并写入 15 台模拟电脑 + 近 7 天模拟数据。

**真实多台电脑测试期间，这个 PowerShell/终端窗口不能关，关了服务端就停了**，所有代理会因为联系不上服务器而把数据攒在本地队列里等重试。短期测试直接留着窗口开着即可；如果要让服务端在没人盯着的情况下长期跑，可以用 [NSSM](https://nssm.cc/) 之类的工具把 `dotnet run`（或 `dotnet MonitorServer.dll`）包装成 Windows 服务，这个第一期暂时没有自带脚本做这件事。

## 三、配置说明

### 3.1 监听端口 / 地址

默认已配置监听 `http://0.0.0.0:5208`（`appsettings.json` 里的 `Urls`），也就是监听这台电脑所有网卡，局域网内其他电脑可以直接用 `http://<这台电脑的内网IP>:5208` 访问管理网页，不用改配置。

如果只想本机测试、不想局域网内其他人能访问，临时改成只监听本机：

```powershell
$env:ASPNETCORE_URLS = "http://localhost:5208"
dotnet run
```

**重要：Windows 防火墙默认拦截入站连接**，如果服务器装的是 Windows 10/11（不是 Server 版的话更常见），即使改了监听地址，其它电脑一般还是连不上，需要在服务器上放行端口（以管理员身份运行 PowerShell）：

```powershell
New-NetFirewallRule -DisplayName "MonitorServer" -Direction Inbound -Protocol TCP -LocalPort 5208 -Action Allow
```

建议只放行公司内网段，不要暴露到公网。

### 3.2 数据库文件位置

默认是 `server/MonitorServer/monitor.db`（SQLite，程序自动创建）。如果要换路径，改 `appsettings.json` 里的 `ConnectionStrings:Default`，例如：

```json
"ConnectionStrings": { "Default": "Data Source=D:/data/monitor.db" }
```

### 3.3 重新生成模拟数据

删除 `monitor.db` 文件，重新 `dotnet run` 即可重新生成 15 台模拟电脑 + 近 7 天数据、默认管理员账号。

### 3.4 管理员账号

种子数据会自动创建一个管理员账号：

- 用户名：`admin`
- 密码：`admin123`

**这是测试账号，正式上线前一定要改掉**（目前第一期还没做"修改密码"页面，临时办法：改代码里 `Data/DataSeeder.cs` 的密码后删 `monitor.db` 重新生成，或直接改数据库里 `AdminUsers` 表的 `PasswordHash`）。

## 四、功能测试清单

启动后浏览器打开服务地址，登录（admin / admin123），按下面清单逐项核对：

### 1. 登录与权限
- [ ] 未登录直接访问 `/Reports`、`/Settings` 等页面，应自动跳转到登录页
- [ ] 账号密码错误时登录页显示"用户名或密码错误"
- [ ] 登录成功跳转到总览页
- [ ] 右上角"退出"能正常登出，退出后再访问任意管理页面应重新要求登录

### 2. 总览页
- [ ] 显示 15 台电脑，每台都有状态标签（干活/空闲/锁屏/关机/离线）
- [ ] 顶部统计卡片（终端总数/在线/正在干活/离线）数字之和逻辑合理
- [ ] 点击某行"查看时间线"能跳转到该设备的时间线页面

### 3. 电脑时间线页
- [ ] 切换设备下拉菜单，数据随之刷新
- [ ] 切换日期（含周末），周末应提示"当天无数据"
- [ ] 开机/关机时间、开机总时长、干活时长四个卡片数字正确
- [ ] 时间条颜色分段（绿=干活、黄=空闲、紫=空闲且锁屏）与下方"分段明细"表格一致
- [ ] "当日前台程序使用排行"列表按时长从高到低排序

### 4. 统计报表页
- [ ] 切换"按日/按周/按月"，统计区间文字相应变化
- [ ] 各电脑汇总表格的开机/干活/空闲时长、干活占比数字合理（干活+空闲 ≈ 开机总时长）
- [ ] 点击"导出 Excel"能下载 `.xlsx` 文件，用 Excel/WPS 打开后数据与网页一致

### 5. 设置页
- [ ] 修改"空闲判断时长"或"数据保留天数"，点保存，刷新页面确认已保存
- [ ] 修改某台电脑的"使用人"或"前台程序记录"开关，点保存，刷新确认已保存
- [ ] 回到总览/时间线页，确认使用人名称已同步更新

### 6. 终端代理（真实电脑）
- [ ] 按 `agent/README.md` 在一台测试电脑上装好代理后，几分钟内该电脑按主机名自动出现在"设置"页列表里
- [ ] 其余代理相关测试项见 `agent/README.md` 第四节"验证清单"

### 7. 其它
- [ ] 连续操作几次登录、改设置后，数据库里 `AuditLog` 表应有对应留痕记录（可用 DB Browser for SQLite 等工具打开 `monitor.db` 查看，不强制要求测试工具，这项供有需要时核查）

## 五、已知限制（第一期范围内）

- 演示数据（15 台模拟电脑）与真实代理上报的电脑并存，互不影响；只是演示数据不是真实采集的。
- 暂无"修改管理员密码"界面。
- 暂无节假日专项配置（设置页目前只有工作时间，没有节假日日历）。
- 代理与服务端之间默认不做身份校验；如需加一层保护，在 `appsettings.json` 里配置 `"Agent": { "ApiKey": "自定义密钥" }`，并在每台电脑安装代理时用 `-ApiKey` 参数传入相同值（见 `agent/README.md`）。
- 其余边界说明（干活/空闲统计的局限、技术上无法防范的情况等）见产品说明书第 6 章。

## 六、停止服务

终端里按 `Ctrl+C`，或者关闭运行它的终端窗口。

## 七、问题反馈

测试中如发现页面报错、数字对不上、或哪个操作不顺手，记录下：**哪个页面 + 做了什么操作 + 期望结果 + 实际结果**，反馈给开发者即可定位修复。
